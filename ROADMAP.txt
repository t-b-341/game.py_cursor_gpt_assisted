3. HOW THE PROGRAM WORKS (AND WHERE CHANGES LIVE)
==================================================

High-level mental model of your project and how it ties to your ideas.


3.1 Entry Point and Main Loop
-----------------------------

Key files:
- game.py – main entry point
- context.py – AppContext: screen, config, resources, telemetry
- state.py – GameState: all mutable game state

Flow:
1) game.py:
   - if __name__ == "__main__": main()
2) main():
   - Initializes Pygame (window, clock).
   - Creates AppContext (GameConfig, asset manager, shaders config, telemetry connection).
   - Creates GameState; sets current_screen to TITLE.
   - Creates SceneStack with TitleScene as top.
3) _run_loop(ctx, game_state, scene_stack):
   - Event loop:
     - Poll events, pass to top scene(s).
     - Update game according to game_state.current_screen.
     - Run systems: movement, collision, AI, audio, telemetry, UI.
     - Render: call draw() on top scene with RenderContext.

Where “game at 0.75x speed” fits:
- dt is passed to systems like movement_system.update(dt, state).
- Add `timescale` to GameConfig and multiply dt in system calls, or scale speeds/cooldowns in config/balance.py and config/game_config.py.


3.2 Game State, ECS, and Systems
--------------------------------

Key files:
- state.py – GameState
- ecs_components.py – data structures for entities
- systems/:
  - movement_system.py
  - collision_* modules
  - ai_system.py
  - spawn_system.py
  - audio_system.py
  - telemetry_system.py
  - ui_system.py
  - registry.py – system ordering

Concept:
- Entities (player, enemies, bullets, pickups) live in lists or ECS structures on GameState.
- Each frame:
  - Movement system applies velocities using dt.
  - Collision systems detect and resolve hits and pickups.
  - Spawn system controls wave logic and spawners.
  - AI system drives enemy behavior.
  - Telemetry system logs events when enabled.

Where your ideas go:
- Respawner enemy / spawner enemy:
  - config/enemy_defs.py and enemy_data: define enemy type with spawn-on-death behavior.
  - systems/spawn_system.py: implement logic that, when that enemy dies, spawns children.
- Chess-piece enemies and special bosses:
  - Add enemy definitions and behavior patterns in enemy config + ai_system.
  - Adjust spawn rules in spawn_system per wave/difficulty.
